01

範例章節：一個請求的旅程

約 30 分鐘・示範所有元件的寫法
這堂課你會學到
  1. 目標一（動詞開頭、可檢驗）
  2. 目標二
  3. 目標三：動手做出某個結果

1. 先建立情境

用一個具體的情境開場：讀者手上有什麼、遇到什麼問題、為什麼需要今天的主題。

Load Balancer（負載平衡器）站在多台伺服器前面，把進來的請求平均分給它們的元件。第一次出現的名詞用這種卡片解釋，一張卡一個名詞，垂直堆疊、佔滿整列。
Health Check（健康檢查）定期確認後端是否還能正常回應；失敗的後端會暫時不分配流量。

【情境】讀者現在卡在哪裡、這張圖要回答的問題是什麼。【需求】為什麼這件事重要、不懂會發生什麼事。【細節】讀圖前需要先知道的一兩個前提或限制。這段要寫成 2～4 句完整敘述，而不是一句標題。

看圖重點：指出眼睛應該先看哪裡（顏色、箭頭、虛線代表什麼），以及看完應該得到哪個結論。

上一張圖說明「有哪些角色」，這張改用並排對照，回答讀者下一個自然的問題：有沒有 Load Balancer，差在哪裡？用承接句把兩張圖串起來，讓讀者知道為什麼要看下一張。

看圖重點：左右兩邊只差一個元件，注意右邊的紅色伺服器故障時，使用者仍然有其他路可走。

生活比喻Load Balancer 像銀行的叫號機：不管哪個櫃台有空，都把下一位客人分過去；某個櫃台暫停服務時，叫號機就不再叫到那裡。

2. 數字與趨勢用圖表呈現

當重點是「隨時間變化」或「數量差距」時，流程圖說不清楚，就改用資料圖表。這段寫出讀者要用圖表回答的問題，以及圖上的數字是示意值還是實測值。

看圖重點：藍線是流量，橘色階梯是伺服器數量；注意擴容永遠比流量晚一步。

3. 設定檔與逐欄位說明

建立 lb.yaml：

name: web-lb               # 名稱
listeners:
  - port: 80               # 對外開放的 Port
targets:
  - host: 10.0.1.11
  - host: 10.0.1.12
healthCheck:
  path: /healthz
  intervalSeconds: 10
📖 逐欄位說明：lb.yaml
name
這個 Load Balancer 的名稱，之後查詢狀態時用。
listeners
要監聽哪些 Port 的清單，每個 - 是一項。
port: 80
使用者連進來的 Port。80 是 HTTP 的預設 Port。
targets
要把請求轉給哪些後端伺服器。
healthCheck
健康檢查設定。
path
檢查時呼叫的網址路徑，回應 200 代表健康。
intervalSeconds
每隔幾秒檢查一次。太短會增加後端負擔，太長則故障發現得慢。
💡 記憶法：用一句話總結這份設定的結構，幫讀者把欄位歸類。

套用並確認狀態：

lbctl apply -f lb.yaml
lbctl get targets --name web-lb
HOST         STATUS     LAST-CHECK
10.0.1.11    Healthy    3s ago
10.0.1.12    Healthy    3s ago      ← 兩台都健康才算成功
常見錯誤把新手最可能犯的錯、症狀與修正方式寫在這裡。

看圖重點：綠色格代表「做得到」，注意沒有任何一個選項全部都綠。
